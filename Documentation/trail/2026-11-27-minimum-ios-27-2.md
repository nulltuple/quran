# Minimum iOS 27.2 for both apps, availability fallbacks removed

- **Date:** 2026-11-27
- **Agent:** Claude Code / claude-opus-5-5
- **Type:** refactor
- **Status:** shipped
- **Related:** roadmap decision D1 ([quran-prioritized-roadmap.md](../agents/quran-prioritized-roadmap.md) §7);
  [2026-11-26-v0-recitation-engine.md](2026-11-26-v0-recitation-engine.md)

App: **both** (Quran and Arabican). QuranEngine's package minimum changed, and Arabican depends on that package.

## Context

The owner: "Please take dependency on latest iOS 27.2 release. I don't want old release hold us back. Make sure you
update spec and anything else needed." Before: QuranEngine `platforms: [.iOS(.v15)]`, the Quran app's targets at 15.0
and 16.4, Arabican's package and app at 17.0. Xcode 27.2 (SDK `iphoneos` 27.2); the simulator runtime iOS 27.2 is
installed.

## Decisions

- **Both apps go to 27.2.** SwiftPM rejects a client whose deployment target is lower than a dependency package's
  minimum, and `ArabicLearning` depends on QuranEngine, so Arabican cannot stay at 17. The owner's "us" covers both.
- **The version is written as a string** (`.iOS("27.2")`): the root manifest's tools version 5.8 has no `.v27` case.
- **Every availability check that 27.2 always satisfies is gone**, with its fallback branch: 104 `#available` /
  `#unavailable` checks and 26 `@available(iOS …)` annotations (iOS 15.1 to 27.1) in 47 files. Checks and fallbacks for
  versions the app can no longer run on are dead code and compiler noise. `@available(*, unavailable)` stays.
  A script took the branch each check always took (`if #available` body; nothing for `guard #available … else`; the
  `else` of `#unavailable`), then I edited three `if`-expressions by hand (`MoreMenuView` now always pushes clear pages,
  `NavigationActionsTests` expects `ellipsis`) and deleted one helper only the fallback used
  (`UIInterfaceOrientationMask.preferredOrientation`). The first script run kept `else` branches glued to the kept
  branch, because a `} else {` line has a net brace count of zero. That run was reverted before it reached a commit, and
  the script was fixed to track braces character by character.
- **Deprecation warnings were not chased.** At 27.2, APIs deprecated in iOS 16–18 warn (`Locale.languageCode`,
  `characterDirection(forLanguage:)`, `components(fromIdentifier:)`, `String(contentsOf:)`,
  `CTFontManagerRegisterGraphicsFont`). Replacing them changes behavior-bearing code in Localization and fonts and
  deserves its own tested change (Follow-ups).
- **AGENTS.md gets the rule** (Identity and branding): minimum iOS 27.2 for both apps, no checks or fallbacks for 27.2 or
  earlier, and raise both manifests and both projects together next time. The "pre-iOS 26 title fallback" UI rule is gone.

## Trade-offs

- **Complexity removed:** 444 lines deleted, 125 added (mostly re-indentation) across 49 Swift files; no new code paths.
- **Who loses:** anyone on iOS 26 or earlier (or a device iOS 27 does not support; that device list is UNVERIFIED here)
  can no longer install new TestFlight builds. Earlier builds keep working. The owner chose this.
- **Upstream merges cost more:** `quran/quran-ios` still supports older iOS, so upstream changes to the 30-odd UIx/NoorUI
  files touched here will conflict where they edit an availability branch. Accepted: these hunks are small and the
  owner asked for no back-compat.
- **Ongoing cost:** none added. Future SwiftUI work (H2's practice UI) can use Observation and current APIs without
  fallbacks.

## Changes

- `Package.swift`, `ArabicLearning/Package.swift`: `.iOS("27.2")`.
- `Example/QuranEngineApp.xcodeproj`, `Apps/Arabican/Arabican.xcodeproj`: `IPHONEOS_DEPLOYMENT_TARGET = 27.2` (4 and 2
  build configurations).
- Availability checks removed in Core (1), Domain (1: `CoreMLRecitationModel` calls the async `prediction` directly),
  UI (32: UIx and NoorUI components, sheets, navigation actions, list items, Quran views and their tests), Features (15),
  ArabicLearning (1). iPhone and iPad alike; no new `#if`.
- Docs: AGENTS.md (CLAUDE.md is its symlink) identity table and rule, README requirement, roadmap D1 and H1/H2 row,
  `quran-roadmap-progress.md`, Arabican `HANDOFF.md` and an ADR-0001 amendment.

## Tests

- **No new tests:** the change removes branches that iOS 27.2 never took; the branches that remain are the ones every
  existing test already exercised on the iOS 27.2 simulator. Tests that guarded on an OS version
  (`guard #available(iOS 16/17) else { return }` or `XCTSkip`) now run unconditionally, as they already did on 27.2.
